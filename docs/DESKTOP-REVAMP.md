# Desktop daily content desk

The default view is **Today**. It shows a useful next step from the real workspace: fix a required setup check, watch a ready cut, inspect a failure, connect publishing, or work on an original idea. Live, Clips, Studio, Growth, System, Settings, and Setup remain available in the navigation.

The daily cut list shows recent scheduled clips, then failures. If no cut is ready, it shows recent rejections with the actual reason. The count is the recent clip library's scheduled cuts, not a claim that the automatic scheduler waits for manual approval. Publishing shows every supported scheduler platform, its configured/enabled state, `ready_now`, actual errors, limits, and current gating reason. Production counts use the engine's live stages and backlog.

Research has a linked source notebook, local search, source selection, a topic form, real agent/model/status details, and persisted draft outputs. Each draft exposes its spoken script, platform copy, evidence links, judge checks, and unsupported claims. Sentence evidence shows the saved quoted excerpts and links for each reviewed script/post sentence, with opinion questions identified separately. Engine warnings override a positive saved judge label and lead the card overview; saved model notes remain available for comparison. Copy buttons copy the saved text. Deletion asks for confirmation and removes only that draft. No research UI action publishes, schedules, or claims to render a video. Busy, empty, failed, interrupted, and older-source states remain visible.

Clip previews show the saved viewer assessment's hook, context, payoff, pacing, confidence, skip/watch reason, flags, and timed evidence. They also expose final rendered-cut checks, issues, and evidence when saved. Older clips retain their original verdict and an explicit note when detailed review is unavailable. Gallery cards now show the real reason instead of relying on a score alone. **Edit in Studio** opens the reviewed cut in the existing editor.

`desk.css` provides the coherent theme over the retained component layout. It removes studs, leather/noise backgrounds, chrome text, glows, blur, and the launch animation. Tonal depth, readable system typography, ember actions, keyboard focus, disabled states, and reduced motion follow the decision sheet in `REVAMP.md`. Existing Studio controls and all schema-generated settings remain intact. Research is grouped explicitly in Settings with a short usage guide.

`desk.js` consumes `/api/state`, `/api/clips`, `/api/setup`, and the shared research endpoints. The existing fast engine poll remains; extra research/library reads occur only while Today or Research is visible and unlocked. Idle research/library refreshes run about every 20 seconds; busy research about every 4 seconds. Source links accept only HTTP(S) and all fetched content is escaped before display.

A pre-existing polling bug was corrected: `phoneChip()` was nested inside `renderForm()` but called from the global state poll. The helper is now in global scope, allowing state polling and the phone-address action to work before Settings is opened.
