# YouTube publishing guidance

Use the clip itself to establish what happened. Research examples inform presentation; private review notes, ratings, selection reasons and diagnostic language never belong in a public title, description, comment or on-screen hook.

| Field | Official YouTube guidance | Ashvane application |
| --- | --- | --- |
| Title | Be accurate and succinct; put important words near the beginning and limit capitals and emoji. [Title and thumbnail tips](https://support.google.com/youtube/answer/12340300?hl=en) | Describe the specific event in the selected cut. Default instructions suggest roughly 4–12 words; that is an editorial preference, not a YouTube rule. No forced capitals or `#Shorts` in the title. |
| Description | Make each description unique, use the opening lines to describe the video, and feature one or two main topic words naturally in both title and description. [Description tips](https://support.google.com/youtube/answer/12948449?hl=en) | Write a brief original first line that adds context. Attribute a participant’s unverified claim. The publisher appends configured source credit; do not replace the opening with review analysis or a keyword dump. |
| Hashtags | Use directly relevant hashtags. Up to three hashtags from the description may appear by the title. [Hashtag guidance](https://support.google.com/youtube/answer/6390658?hl=en) | Visible hashtags are separate from API tags. The default limit is three relevant hashtags, with no minimum. Three is the app’s default, not YouTube’s overall hashtag allowance or a promise that all three display. |
| Tags | Tags have a minor discovery role, with particular usefulness for commonly misspelled terms. [Video tags guidance](https://support.google.com/youtube/answer/146402?hl=en) | Optional API metadata can include relevant names or spelling variants. Do not confuse tags with visible hashtags or treat tag volume as a growth strategy. |

These four sources share one origin: YouTube’s own Help documentation. They are publishing guidance, not independent evidence that any observed creator’s metadata caused its view count. The [20-source streamer study](STREAMER-CLIP-STUDY.md) supplies qualitative format observations separately.

## What the current pipeline enforces

The writer receives speech within the selected cut, its own sampled frames, channel/category and the public source URL. Its brief excludes private verdict reasons, suggested judge titles/captions, reviewer evidence, visual review prose and discovery chat. Researched examples are labeled as untrusted style references and cannot establish facts about the candidate.

Public copy must have fresh video-origin provenance (`_source=video`) and the target platform’s required text. Missing or invalid writer output holds processing; legacy copy is held before upload without counting an upload attempt. No platform substitutes a judge caption when writing fails.

The guard checks configured diagnostic patterns and substantial word-for-word overlap with private notes, including comments, hooks and final composed templates. Independently observed source dialogue may overlap; final review observations are excluded from the overlap source because they can quote the public hook. Structural separation is the main protection. The guard is additional defense and does not detect every paraphrase.

The YouTube publisher keeps visible hashtags separate from API tags, and recording a post captures the public title actually sent. Analytics does not fall back to a private judge title. Relevant limits and styles remain configurable; model instructions guide wording, while provenance and public-text validation control whether publication proceeds.

## Audience-facing example

**Title:** N3on Mishears Nina Talking About Adoption

**Description:** Nina explains her plans, and N3on mixes up two words.

**Relevant hashtags:** `#N3on #IRL`

This names the observed misunderstanding without implying pregnancy or explaining why an editor selected the moment. It is an example, not a tested growth claim.
