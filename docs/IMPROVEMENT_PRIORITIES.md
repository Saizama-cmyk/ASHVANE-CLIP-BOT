# Improvement priorities

Recommendations from the 13 October 2026 source review and public product research,
updated 14 October for compilation source progress. These are proposals and remaining
acceptance work, not promised results. Keep all four
businesses, account bindings and manual run switches independent.

| Priority | Proposal and reason | Acceptance evidence | Tradeoff |
|---|---|---|---|
| 1 | A release evidence index joining source commit, source checks, frozen smoke checks, installer hash and served assets | One versioned receipt that distinguishes source/build/install; stale runtime negative control | More release bookkeeping; prevents misleading done claims |
| 2 | Native iPhone/Android validation of Interstellar, authentication, Core controls and media caches | Actual signed/sideloaded package on hardware, background/resume and token-boundary checks | Device/CI time; browser fixtures remain valuable but insufficient |
| 3 | A fixed held-out Surge quality set including jokes, no-speech gameplay, noisy sources and caption/trim failures | Separate false accepts/rejections, full preview/audio review and source-group holdout | Editorial labeling effort; fewer convenient but misleading aggregate scores |
| 4 | A per-job production/evidence inspector with a consistent vocabulary across the four studios | Requested/running/held/partial/finished labels match real receipts, with no phantom progress | UI integration work; simplify dense diagnostics progressively |
| 5 | Real Core operating trials on bounded, owner-approved problems after installation | Actual receipts, expected failing reproductions, independent review, current hashes, rollback exercise and business contention check | Slower than unconstrained self-editing; produces defensible outcomes |
| 6 | Outcome calibration only after enough profile-owned audience reports exist | Unknown rows retained, sample thresholds and source-group evaluation; compare decisions before/after | Cold-start delay; avoids fitting five reported videos as a universal strategy |
| 7 | General long-video ingest and reviewable tight/context variants for Surge | Rights-aware local-file/URL intake, bounded jobs, each variant reviewed and duplicate publication prevented | Storage/inference load; a useful broader workflow rather than a virality promise |
| 8 | Caption-safe areas and multi-speaker crop tracking | Adversarial portrait/landscape fixtures and full-output review on intended destinations | More rendering complexity; captions must not hide gameplay/UI or faces |
| 9 | Complete release validation of the source-implemented Hollow compilation workflow | Focused real ffmpeg and orchestration/API checks passed; full suite (1,110 passed/five skipped), 70 frozen checks and installed asset/auth checks now passed; next review real production compilations | Longer render/storage demand for preserved source copies; verify real chapter/audio continuity and public claims |
| 10 | Resonance loudness/true-peak measurement and a repeated native listening protocol | Appropriate installed measurement tools, decoded exports, level-matched auditions, actual listener availability | No universal target across genres; preserve creative judgment |
| 11 | Social Studio approval/export packages before direct publishing | Client-scoped review, explicit approval records, original asset rights and destination identity preview | Manual last mile initially; account connection must be designed separately |

The [AutoClip review](AUTOCLIP_COMPARISON.md) suggests useful interaction patterns:
channel intake, visible source-to-output workflow, paired variants and explicit
brand/safe-area controls. Adopting those ideas does not require copying its branding,
adding a paid AI API or treating its marketing claims as test results.

Design should concentrate the observatory signature in navigation and Core, preserve
reading contrast, and make error/empty/loading/retry states as polished as success.
Phone layouts should put current work, blockers and one clear next action before
ornament. Accessibility and reduced motion are operational features for long sessions.

No item here establishes a revenue forecast. Evaluation should report real production
time, editorial yield, failed work, cost of operation and available audience outcomes.
